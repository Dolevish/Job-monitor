# Job Monitor

סורק כל 30 דקות את מערכות הגיוס של חברות היעד, מסנן משרות ג'וניור ב-Embedded / Firmware / Network בישראל,
ושולח לטלגרם רק משרות חדשות. רץ על GitHub Actions.

## איך זה עובד
1. `companies.yaml` מכיל את כל 72 הרשומות ברשימת היעד. הסריקה כוללת מערכות גיוס, אתרי חברות ולוחות חלופיים לפי מזהה מעסיק.
   נוספו Apple, Google, Oracle HCM, Ashby, SuccessFactors, Taleo, HiBob, אתרי חברות וחברות השמה.
   חברות שמסומנות `detect` מזוהות מדף הקריירה; חברה ללא מקור מזוהה מוצגת כפער בדוח הכיסוי.
   Annapurna/Amazon ו-Palo Alto/CyberArk משתמשות במקורות משותפים, וכל מקור נסרק פעם אחת.
2. כל משרה נשמרת לפי ה-ID שלה במקור, אז משרה שכבר ראית לא תגיע שוב.
3. סינון: כותרת (`config.yaml`) ← מיקום בישראל ← השכלה נדרשת ← שנות ניסיון מתוך תיאור המשרה.
   שורות שמסומנות כיתרון ("advantage", "יתרון", "Nice to have") לא נספרות.
   תואר שני/דוקטורט חובה נפסלים; דרישה שמאפשרת גם תואר ראשון או תואר מתקדם כיתרון אינה נפסלת.
4. 🟢 = מתאים. 🟡 = חסר מידע על ותק או שמדובר בתחום משיק, כמו אלגוריתמים/ML ו-CAD/Emulation לבוגרים.
   משרות זמניות מסומנות בהודעה.

## הקמה (פעם אחת, ~15 דקות, עדיף ממחשב)

**1. בוט טלגרם**
- בטלגרם: פתח את `@BotFather` ← `/newbot` ← תן שם. תקבל **token**.
- שלח לבוט החדש הודעה כלשהי (למשל `hi`).
- פתח בדפדפן: `https://api.telegram.org/bot<TOKEN>/getUpdates` וחפש `"chat":{"id":...}` — זה ה-**chat id**.

**2. ריפו ב-GitHub**
- צור ריפו חדש, **Private**, בשם `job-monitor`.
- העלה את כל הקבצים מה-zip, **כולל התיקייה `.github`** (ב-Mac היא מוסתרת: Cmd+Shift+. ב-Finder).
  או מהטרמינל:
  ```bash
  cd job-monitor
  git init && git add . && git commit -m "job monitor"
  git branch -M main
  git remote add origin https://github.com/<USER>/job-monitor.git
  git push -u origin main
  ```

**3. סודות**
Settings ← Secrets and variables ← Actions ← New repository secret:
- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_CHAT_ID`

**4. ריצה ראשונה**
Actions ← job-monitor ← Run workflow. תקבל בטלגרם:
- סיכום זיהוי מערכות הגיוס של החברות שסומנו `detect`.
- "קו בסיס נשמר" + עד 10 משרות מתאימות ועד 5 משרות לבדיקה שפתוחות כרגע.
מכאן והלאה הוא רץ לבד כל 30 דקות ושולח רק משרות חדשות. אם אין חדשות — שקט.

## כיוונון
- `config.yaml` — מילות מפתח, `title_adjacent`, `bachelors_compatible`, ערים, `max_years`, ושליחת 🟡.
  `baseline_max` ו-`baseline_review_max` מגבילים בנפרד את התראות קו הבסיס; `send_review: false` מבטל 🟡.
- `companies.yaml` — אם ידוע ה-ATS, הגדר `ats` + `board`; אחרת `status: detect` + `careers` (כתובת קריירה מדויקת), או `domain`.
  Eightfold משתמש ב-`board: "careers-host|domain"`; Qualcomm ו-Microsoft משתמשות ב-API הציבורי PCSX.
- בדיקה מקומית: `pip install -r requirements.txt` ואז `python -m monitor --dry-run --only nvidia -v`.
  הרצה יבשה משתמשת בעותק בזיכרון של ה-state ואינה שומרת משרות או מסמנת הודעות כנשלחו.
  גם GitHub Actions אינו שומר cache חדש כש-`dry_run` מסומן.

## הרצה לאחר עדכון

אין צורך לאפס את ה-state. המקורות הקיימים שומרים על מזהי המשרות שלהם, ומקור חדש מקבל קו בסיס משלו.
ב-GitHub: Actions ← job-monitor ← Run workflow ← סמן `dry_run` לבדיקה ראשונה.
בסיום, פתח את הלוג ואת קובץ `coverage.json` שב-artifact בשם `source-coverage-…`.
לאחר הבדיקה אפשר להריץ ללא `dry_run`; התזמון הקיים נשאר כל 30 דקות.

להרצה מקומית, מתוך תיקיית הפרויקט (Python 3.12):

```bash
git pull
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m monitor --dry-run -v --coverage-json state/coverage.json
```

ב-Windows מפעילים את הסביבה עם `.venv\Scripts\activate`.
הרצה יבשה אינה שולחת הודעות ואינה משנה את בסיס הנתונים הקיים.
אפשר לצמצם חברה באמצעות `--only matrix` או לבדוק רק את רשימות המשרות:

```bash
python -m monitor --check-sources --coverage-json state/sources.json
```

`--check-sources` אינו מוריד תיאורים פרטניים, אינו שולח לטלגרם ואינו משנה state.
הוא מחזיר קוד 1 אם יש מקור שנכשל או חברה ללא מקור; זו אינה טענה שהחברה אינה מגייסת.
בדיקת הסינון והתיאורים המלאה נעשית עם `--dry-run`.

הרצה רגילה: הגדר `TELEGRAM_BOT_TOKEN` ו-`TELEGRAM_CHAT_ID` במשתני הסביבה ואז `python -m monitor -v`.
לבדיקות הקוד:

```bash
python -m pip install pytest
python -m pytest -q
```

## זמן ריצה ו-GitHub Actions

הרחבת הסריקה מוסיפה בקשות, ובקו הבסיס מורידים גם תיאורים למשרות מועמדות לסינון.
משך הריצה תלוי במקורות ובניסיונות החוזרים. בדוק את משכי הריצות ואת מכסת Actions בחשבון;
התדירות של כל חצי שעה אינה מבטיחה שימוש במסגרת מכסה חינמית.

## התחלה מחדש
Actions ← job-monitor ← Run workflow ← סמן **reset_state**. הריצה תבנה קו בסיס חדש ותזהה מחדש את כל החברות.
עדכון הגלאי והמסנן אינו דורש איפוס: זיהויים ישנים מתרעננים, ומשרות `review` עד שלושה ימים אחורה
שלא קיבלו הודעה במדיניות קו הבסיס הישנה נבדקות שוב פעם אחת. הודעות שכבר נשלחו אינן נשלחות מחדש.

## התראות תקלה
מקור שנכשל 6 ריצות ברצף (~3 שעות) שולח ⚠️ לטלגרם פעם אחת, עד שהוא חוזר לעבוד.
אם טלגרם נכשל (למשל chat id שגוי), ההודעות נשמרות בתור ונשלחות בריצה הבאה שמצליחה (עד 3 ימים אחורה).
הלוג מציג את הסיבה המדויקת שטלגרם החזיר.
כשל בשליחה גורם לריצה להסתיים בקוד שגיאה; ה-state עדיין נשמר כדי לאפשר ניסיון נוסף.
כשל בהורדת תיאור אינו נחשב "לא צוין ותק": המשרה תיבדק שוב בריצה הבאה.

## קריאת הלוג
- `fetched` — מספר המשרות שהמקור החזיר לפני הסינון (ייתכן שהוא כולל משרות מחוץ לישראל).
- `new` — משרות שטרם נשמרו במערכת; בקו הבסיס אלה משרות קיימות, לא בהכרח פרסומים מהיום.
- `cand` — משרות חדשות שעברו את הסינון הראשוני ויש להן תיאור שניתן לסווג.
- `coverage` — כיסוי בפועל, בנפרד ממספר המקורות המוגדרים:
  `configured` רשומות ברשימה; `polled_entries` רשומות שנוסה המקור שלהן; `feeds` מקורות נפרדים;
  `successful_entries` רשומות עם משרות ובלי כשל בהורדת תיאור; `empty_entries` מקורות ריקים;
  `partial_entries` כשחלק מהתיאורים נכשלו; `failed_entries` כששליפת הרשימה נכשלה; `skipped` ללא מקור זמין.
- `secondary_entries` — רשומות שמשתמשות בלוח חיצוני. הופעה ברשימה זו אינה מעידה שכל משרות החברה מכוסות.
- `filters` — עם `-v`, מונים לסיבות הסינון: כותרת, מיקום, משרה שכבר נשמרה, ותק, השכלה והתאמות.
- `WARNING empty feed` — מקור החזיר אפס משרות; יש לאמת את ה-board ולא להסיק אוטומטית שאין משרות.
  `new=0` לצד `fetched>0` הוא מצב תקין. `RETRY details next run` מציין תיאור שינוסה מחדש.
הגלאי מדלג על קישורי CSS/תמונות/ניוזלטרים, מגביל סקריפטים, ומפסיק לנסות נתיבים נוספים על host שחסם ב-403/429.

## מקורות ופערים ידועים

המיפוי והאימות מפורטים ב-[COVERAGE.md](COVERAGE.md). קובץ JSON חדש נוצר בכל ריצה שבה מצוין `--coverage-json`.
גם כשדף מחזיר HTTP 200, דף כניסה, מבנה לא מוכר או דפדוף חסר גורמים לדיווח כשל.
מקורות עם תוצאות מרובות נסרקים דרך כל העמודים; קישורים כפולים מנוכים לפי מזהה המשרה.

לוחות Jobify ו-Jobnet משמשים מקורות חלופיים לפי מזהי מעסיקים שאומתו, ומסומנים גם בהודעת המשרה.
הם עלולים להתעדכן באיחור או להציג רק חלק ממשרות החברה. אין הבטחה לכיסוי מלא של לוחות דרושים או AllJobs.

| חברה | פער ידוע בבדיקה מ-2026-10-06 |
|---|---|
| ACM | קישור Drushim המקורי אינו מזהה עוד את החברה. נדרש קישור קריירה או שם משפטי מלא. |
| Hailo | חשבון Comeet הישן הושבת; טרם זוהה מקור רשימות פעיל. הגלאי ממשיך לנסות לפי מדיניות המטמון. |
| Teva | אתר הקריירה מפנה לדף כניסה, ולכן אינו מספק רשימה ציבורית לסורק כרגע. |
| SanDisk | הלוח הציבורי החזיר אפס משרות. |
| Check Point | המקור הרשמי חסום לסורק; עמוד המעסיק החלופי ב-Jobnet החזיר אפס משרות. |

לכן אין לפרש `polled_entries` ככיסוי מלא של כל החברות. גם משרה שנמשכה בהצלחה עדיין צריכה לעבור את מסנן התחום, ישראל, ההשכלה והוותק.
